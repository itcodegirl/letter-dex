# Adult-led counting pilot

Use [contract v1](../learning/counting-evidence-contract-v1.md). One short quest
is enough; stopping earlier is valid. There is no timed test and no requirement
to finish or intentionally make mistakes.

## Prepare

Record the build, device, browser, input method, and origin. Keep existing saves.
Start the game with `npm start` and open `http://127.0.0.1:4173/` on that laptop.
If another port is supplied for the session, use that exact link throughout.
Saves belong to the browser and origin, including its port.

`127.0.0.1` and `localhost` only reach the device on which the server is running.
An Android tablet needs a separately verified reachable private HTTP(S) address;
the current development server listens on the laptop only. Do not count a
laptop session or a resized desktop browser as physical Android validation.

Choose **Math adventure**, then **Listen**. The adult checks volume and whether
the question is audible. If the saved route opens Bridge Builders or Beacon
Rescue, record that stage; do not erase progress to force Berry Crossing.
Pause the counting pilot and arrange a separate fresh browser profile if needed.

## Observe together

1. Let the child respond to the first two or three questions. Do not point to
   the answer. Replay Listen if wanted. Record quantities, first choices, and
   any help; assist whenever requested.
2. If an error occurs naturally, observe the feedback and next attempt. Do not
   ask the child to fail for testing. If no error occurs, mark retry unobserved.
3. When help is wanted, let the child tap berries to count along. Record when
   spoken numbers/labels or adult help were used. Mark this as supported practice.
4. If the child wants to finish eight successes, observe the footprints,
   greeting, and journal. Ask what the next picture/button seems to mean before
   explaining. Observe the child's chosen next action; continuing is optional.
5. At a convenient break, note the route and earned progress, return to camp,
   refresh, and re-enter math. Check that earned progress remains. A newly
   selected question after reload is not itself lost earned progress.

Ask only what is useful: "What do you think you do here?" or "What happened?"
Record the response rather than interpreting silence as lack of knowledge.
Keep software automation and its audio separate from the child session.

or stutter, help discoverability, whether the child wanted to continue/stop,
and refresh/re-entry results. Do not record private identifiers or audio/video
for this pilot. Describe observations briefly in the dated results file.

Close with one of: proceed with this slice, correct and repeat specified checks,
or insufficient evidence. This decision concerns usability of the tested slice,
not a grade or diagnosis. Android validation and any blocking corrections remain
open until actual observations and retests are recorded. Jenna decides when the
expansion freeze can be lifted.
